# v0.1.0 Release Extraction Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract all non-concierge, non-autonomous-skill-development changes from `feat/concierge` into a release branch, add semantic versioning tooling, and merge to `main` via a pre-vetted integration PR.

**Architecture:** A staging branch `release/v0.1.0` off `main` collects six reviewed sub-PRs (core config, operations, agents, protocols, tools/bin, semantic versioning). Each sub-PR is a feature branch off `release/v0.1.0`. After all sub-PRs merge, a final PR merges the fully vetted `release/v0.1.0` into `main`.

**Tech Stack:** Git (checkout-based extraction; no merge base exists between branches), uv, commitizen (semantic versioning + conventional commits), pre-commit with pre-commit-uv, GitHub Actions

## Context

### Why this approach

- `feat/concierge` and `main` share content but have **no merge base** (different initial commit SHAs from a historical force-push). Standard merge/rebase/cherry-pick strategies fail.
- `git checkout feat/concierge -- <paths>` is the extraction mechanism: it overwrites the working tree + index to match the source branch state. Deletions require explicit `git rm`. Partial merges (pyproject.toml) use `git checkout -p`.
- History is not preservable without `--allow-unrelated-histories`, which produces conflict on every shared path. A clean squash-style extraction with a detailed commit message documenting provenance is the optimal tradeoff.

- [ ] **Step 4: Create .github/workflows/release.yml**

    ```yaml
    name: Release

    on:
      push:
        branches: [main]

    permissions:
      contents: write

    jobs:
      release:
        name: Bump version and release
        if: "!startsWith(github.event.head_commit.message, 'bump:')"
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
            with:
              fetch-depth: 0
              token: ${{ secrets.GITHUB_TOKEN }}

          - name: Install uv
            uses: astral-sh/setup-uv@v4

          - name: Install commitizen
            run: uv tool install commitizen

          - name: Configure git
            run: |
              git config --local user.email "github-actions[bot]@users.noreply.github.com"
              git config --local user.name "github-actions[bot]"

          - name: Bump version
            id: cz
            run: |
              cz bump --yes --changelog 2>&1 | tee /tmp/cz-output.txt
              echo "version=$(cz version --project)" >> "$GITHUB_OUTPUT"
            continue-on-error: true

          - name: Push changes
            if: steps.cz.outcome == 'success'
            run: git push --follow-tags

          - name: Create GitHub Release
            if: steps.cz.outcome == 'success'
            env:
              GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
            run: |
              VERSION="v${{ steps.cz.outputs.version }}"
              gh release create "$VERSION" \
                --title "$VERSION" \
                --notes-file /tmp/cz-output.txt \
                --latest
    ```
