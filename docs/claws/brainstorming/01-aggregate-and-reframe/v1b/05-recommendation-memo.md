# Recommendation Memo

## Executive summary

The field narrows cleanly to three surviving architecture families. The main reason is not raw feature count; it is whether the candidate can make memory-native intelligence the lead dimension while still composing into one coherent Bureau system.

The shortlist is:

1. Bureau-native control stack
2. Letta-led memory spine with Bureau governance
3. Bureau-synthesized superset

These survive because they keep Bureau in the governance loop, preserve a plausible path to memory-native compounding, and do not collapse into awkward bundles. The Hermes-led gateway family and the OpenClaw / Memoh breadth shell remain important reference points, but they are not as strong as shortlist candidates on the combined test of memory lead, composability, and long-term moat.

## Recommended shortlist

| Candidate | Why it stays on the list | Concierge treatment | Autonomous skill evolution treatment | Future unit |
|---|---|---|---|---|
| Bureau-native control stack | Highest coherence and cleanest Bureau ownership; strongest when governance and execution matter more than external surface breadth. | Transformed into a Bureau-owned front door and policy surface. | Transformed into a Bureau-gated observe → propose → promote loop. | Policy capsule |
| Letta-led memory spine with Bureau governance | Strongest explicit memory-native architecture; best fit when the lead dimension must be durable memory and controlled recall. | Hybridized into a Bureau front door plus Letta-backed memory context. | Transformed into memory promotion and rollback under Bureau review. | Memory contract |
| Bureau-synthesized superset | Highest upside if Bureau can keep boundaries crisp; best expression of composability if the pieces actually stay multiplicative. | Transformed into a Bureau-mediated gateway that borrows strong surface behavior without surrendering ownership. | Transformed into a Bureau-gated memory / skill promotion loop. | New synthesis |

The two near-miss families are worth remembering, but not shortlisting:

- Hermes-led gateway and evolution stack: strong on assistant learning, but mixed on maturity and canonical identity, which makes it too unstable for the lead-memory question.
- OpenClaw / Memoh breadth shell: strong on surface breadth, but breadth raises governance burden and weakens the chance of a coherent superset.

## Why these candidates survive

The Bureau-native control stack survives because it is the most legible sovereignty-first design. It keeps policy, memory governance, and execution contract ownership inside Bureau. That makes it the safest path to coherence, but it risks underdelivering on compounding memory unless Bureau closes the memory gap with a stronger compiler or governed attachment.

The Letta-led memory spine survives because the corpus repeatedly treats explicit memory hierarchy as one of the strongest stable ingredients. This family best matches the lead criterion if Bureau wants memory-native intelligence to do the heavy lifting. It survives even with the integration burden because its memory contribution is hard to replace with lighter-weight patterns.

The Bureau-synthesized superset survives because the corpus repeatedly suggests that no single external platform wins all layers. If Bureau can hold the canonical record and promotion rules while borrowing the strongest ingredients from Letta, Hermes, and OpenHands, this family has the highest multiplicative upside. Its weakness is not conceptual fit; it is integration burden and the risk of becoming a clever bundle instead of one system.

The cut line is simple: if a candidate weakens memory-native intelligence, fragments ownership, or turns Bureau into a client rather than the contract owner, it drops out. That is why the breadth-first shells are not shortlisted, even though they have useful assistant-surface patterns.

## How to interpret deletion / hybrid / continue

These lenses still help, but only as shorthand for ownership changes, not as final architecture labels.

- `deletion` means a current Bureau layer stops being a separate product-shaped surface and gets subsumed into a stronger owned unit.
- `hybrid` means Bureau and an external ingredient intentionally share responsibility across a boundary.
- `continue` means Bureau keeps the current scaffolding only if it can still compete on the lead criterion, memory-native intelligence.

Across the shortlist, none of the serious candidates is a pure continue. Each one changes how Bureau owns concierge, memory, or evolution. The real decision is not whether to preserve the current forms, but which ownership pattern gives Bureau the best chance of becoming a coherent superset.

## Specific implications for concierge

Concierge is not a separable afterthought in any surviving candidate. It either changes shape or gets absorbed into a broader front-door design.

| Candidate | Concierge treatment | What that means |
|---|---|---|
| Bureau-native control stack | Transformed | Concierge becomes Bureau's own front door and policy surface. |
| Letta-led memory spine with Bureau governance | Hybridized | Concierge becomes a Bureau front door that draws on Letta-backed memory context. |
| Bureau-synthesized superset | Transformed | Concierge becomes a Bureau-mediated gateway synthesized from the strongest surface patterns. |

This is not just a UI question. Concierge ownership determines who gets to interpret user intent, hold session state, and decide what enters the durable core. The more that responsibility stays inside Bureau, the more the architecture behaves like one system.

## Specific implications for autonomous skill evolution

The dynamic-skill-evolution scaffolding also changes shape in every surviving candidate. None of the shortlist candidates keeps it unchanged.

| Candidate | Dynamic-skill-evolution treatment | What that means |
|---|---|---|
| Bureau-native control stack | Transformed | Evolution becomes a Bureau-gated observe → propose → promote loop. |
| Letta-led memory spine with Bureau governance | Transformed | Evolution becomes memory promotion and rollback under Bureau review. |
| Bureau-synthesized superset | Transformed | Evolution becomes a Bureau-gated memory / skill promotion loop. |

The future unit is not a bare skill in any of the surviving candidates. In the control stack it is a policy capsule; in the Letta-led family it is a memory contract; in the synthesized superset it is a new synthesis that bundles memory, gateway, execution, and promotion boundaries into one governed design. That coupling is the central architectural question, not an implementation detail.

## Recommended next task

The single next task that sharpens the surviving space best is memory-governance design.

That task should answer, at minimum:

- who owns the canonical memory record,
- how promotion and rollback work,
- whether concierge and evolution share the same boundary or use separate ones,
- and how Bureau preserves policy authority if it adopts a memory spine or a synthesized superset.

This is the hinge that distinguishes the shortlist candidates more sharply than any additional platform comparison would.
